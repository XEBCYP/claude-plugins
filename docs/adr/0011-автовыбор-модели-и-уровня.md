# Модель и уровень усилий — выбирает сама сессия

Статус: принято — решение пользователя 2026-10-25: «Давай автоматизируем этот процесс. И без моего участия, чтобы я
не нажимал на клавиши»; «по умолчанию стоит опус 5.5»; «На сверхвысокий переходить не будем. То есть вот максимум на
высокий»; «От опус низкий, средний, высокий до сонета»; «когда отправляет на слепую проверку, он может поставить опус
высокий». Схема показана окном, ответ — «Да, делать». Рамки изменены 2026-10-27 — ADR 0013 (только Opus 5.5,
от среднего до сверхвысокого).

## Что проверено (код приложения 2.1.308, его типы и документация API)

- Инструменты приложения `set_session_effort` / `set_session_model` **отказывают для своей сессии**: «a session must
  not silently re-price its own turns». Для чужой — выше своего уровня или дороже модели — с подтверждением
  пользователя.
- `start_session` принимает `model` и `effort` **не выше своих**; выше — молча игнорируется.
- Мод может переписать `effort` и `model` **каждого запроса к модели** (`turn.step`), своей сессии и агентов, и
  параметры любого вызова инструмента (`tool.call`), в том числе `Agent` и `start_session`.
- Смена `effort` сбрасывает кэш переписки, смена модели — весь кэш (кэш привязан к модели). На переписке в 100 тыс.
  токенов сброс Opus стоит около $0,50, обычный ход по кэшу — около $0,04.

## Решение

- Диапазон: Sonnet 5.5, Opus 5.5 низкий / средний / высокий. По умолчанию — Opus средний.
- Мод `sreda` (`hooks/uroven.ts`):
  - в начале хода пользователя оценивает сообщение без вызова модели: длиннее 1500 знаков, от 3 вопросов, от 4
    пунктов или слова о поиске ошибок, повторной попытке, расхождениях, решениях и вариантах (русские и английские)
    → высокий; короче 300 знаков со словами механики (покажи, закоммить, отправь, найди…) → низкий; иначе средний;
    короткое «да», «давай» — уровень как был; первая строка `Effort: low|medium|high` (задание подпроекту) — этот
    уровень; ответы из панели, документ передачи и сообщения приложения не оцениваются;
  - инструмент `uroven` — сессия сама поправляет уровень по ходу работы;
  - повышение — сразу; понижение по оценке — сразу, пока переписка не длиннее 40 тыс. токенов, дальше — только если
    и следующее сообщение просит ниже (разовая простая просьба кэш не сбрасывает); `uroven` понижает всегда — сессия
    решает сама, описание инструмента предупреждает о цене;
  - уровень ставится каждому запросу своей сессии; запросы агентов — не выше высокого, их модель Haiku → Sonnet,
    Fable → Opus (модель могла прийти из описания агента мимо вызова); агент уровень основной сессии не меняет;
  - вызовы `Agent`, `start_session`, `set_session_model`, `set_session_effort` выправляются в рамки: Haiku →
    Sonnet, Fable → Opus, xhigh/max → high; слепая проверка (слово «слепая»/«blind») → Opus высокий; `Explore` без
    модели (шёл бы на Haiku) → Sonnet;
  - текущий уровень — в строке состояния.
- Модель своей сессии не меняется никогда. Sonnet — только для агентов и подпроектов при запуске.
- Уровень подпроекта глобальная пишет первой строкой задания (`Effort: high`): параметр `effort` при запуске мод
  подпроекта перебил бы своей оценкой, а выше своего уровня глобальная запустить не может. Sonnet — `model:
  "claude-sonnet-5-5"`.
- Правила выбора — `sreda:kak-rabotat`, раздел 10; для подпроектов — `sreda:globalnyj-proekt`, раздел 4.

## Почему

Нажимать переключатели при многих параллельных сессиях пользователь не будет, а один уровень на всё — либо дорого,
либо слабо на сложном. Оценка в начале хода бесплатна, точную поправку делает сама сессия, когда прочитала задачу.
Порог понижения не даёт «экономить» сбросом кэша.

## Не проверено

- Как приложение передаёт смену уровня в API: обычным параметром (сброс кэша переписки) или особым сообщением без
  сброса. От этого зависит, не слишком ли осторожны порог 40 тыс. и правило второго сообщения — проверить по
  расходу токенов после внедрения.
- Есть ли в приложении `agentId` у вызова инструмента из агента и свой ли экземпляр модуля у каждой сессии — тесты
  это только имитируют.
- Работа вживую: после установки и перезапуска приложения посмотреть строку состояния и расход.
