# Отправка в GitHub — глобальный проект отправляет и все подпроекты

Статус: принято — решение пользователя 2026-10-24: «если я даю указание глобальному проекту сделать commit and push,
то он дает такое же указание своим подпроектам. И все одновременно отправляется на GitHub. Мне не придется
контролировать, чтобы все подпроекты были актуальны на GitHub» — «запишем его в общие правила при работе вот с
глобальными проектами»; дополнение: «глобальный проект проверяет, если вдруг какой-то подпроект еще выполняет
какие-то важные вычисления, операции, то он передает ему команду сделать коммит и пуш после завершения этих операций.
То есть глобальный проект как раз все и контролирует».

## Что было

Каждый подпроект — свой git; глобальный проект хранит только ссылки, и его отправка подпроекты не отправляет.
24.10.2026 четыре проекта одного глобального (включая сам глобальный) были только на сервере, у одного подпроекта
лежали неотправленные коммиты; сессия одного подпроекта была занята длинным ходом — отправлять её папку в это время
пользователь запретил: «Там не закончилась, мы даже не можем ее очистить».

## Решение

Раздел 7 навыка `sreda:globalnyj-proekt` (sreda 1.1.2), шаблоны сообщений — в `shablony.md`, строка — в блоке
`templates/user-CLAUDE.md`:

- «Закоммитить и отправить» глобальному — команда и всем подпроектам реестра.
- Глобальная сначала смотрит, кто чем занят. Свободным — сразу; занятым (вычисления, перенос данных, запись в базу) —
  «после текущей операции»; за занятых не коммитит и их папки не отправляет.
- Подпроект без работающей сессии: всё закоммичено — глобальная отправляет сама; есть незакоммиченное — показывает
  пользователю.
- Нет репозитория — только закрытый, после проверки истории на секреты и персональные данные.
- Без `--force`, без переписывания истории, без слияния PR.
- Глобальная ведёт отправку до последнего подпроекта: список ждущих — в `docs/Передача_сессии.md`, проверка по
  `git status`, напоминания; сводка пользователю и строка «отправка закончена».
- В реестре у каждого подпроекта — адрес GitHub и последняя отправка; новый подпроект — сразу с закрытым репозиторием.

## Что отвергнуто

- Один репозиторий на весь глобальный проект или подмодули git: переезд папок и путей во всех заданиях, а подмодули
  всё равно отправляются каждый отдельно.
- Отправка всего одной командой глобальной сессии по всем папкам сразу: она закоммитила бы недоделанное и мешала бы
  занятым сессиям.
- Буквально «одновременно»: занятая сессия читает сообщение только после своего хода, поэтому отправка — сразу у
  свободных и после операции у занятых, а глобальная доводит до конца.
