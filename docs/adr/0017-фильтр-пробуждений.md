# Узкий фильтр пробуждений по итогам второго дня записи

Статус: принято — решение пользователя 2026-10-28: на вопрос «Делать фильтр пустых пробуждений глобальной сессии?» —
«Узкий фильтр (рекомендую)»; и «Работу журнала записей сохрани, чтобы пособирать еще аналитику за больший период.
Может быть, на большем сроке у тебя появятся какие-то новые мнения по оптимизации фильтров.» Выпуск: sreda 1.11.0.
Продолжает ADR 0015 (пункт 6) и ADR 0016.

## Что показал второй день (27.10 19:39 – 28.10 06:14, глобальная FlowerMarket_App)

Все 15 пробуждений с полем `tools` сверены с перепиской глобальной (`069400f7…`, `668eaea1…`):

| Что пришло от подпроекта | Сколько | Что сделала глобальная |
|---|---|---|
| Отчёт с результатом, решением, нужна команда | 6 | окно пользователю, сообщение подпроекту, проверка |
| Путь к документу передачи подпроекта | 2 | в одном — прочитала документ и нашла настоящую причину ошибки R76; в другом — пересказ |
| Промежуточный отчёт («тесты идут», «шаг сделан, дальше…») | 4 | пересказ пользователю |
| Одно ожидание («Тесты ещё идут; жду результата.» и т. п., три подряд за 2 минуты) | 3 | пересказ |
| «Prompt dropped by a hook: Контекст 160 тыс…» | 1 | посмотрела события подпроекта, пересказ |

Пробуждение с пересказом стоит ~140–270 тыс. входных токенов (почти всё — чтение кэша). Бесполезных — около 1 млн
токенов в день; это доли процента расхода, главная польза — пользователь не получает «всё ещё ждёт» по три раза.

## Решение

| № | Что | Где |
|---|---|---|
| 1 | Пробуждение не идёт в сессию (`drop`), если каждый отчёт в нём — либо отказ хука автопередачи, после которого сообщение дойдёт само («уйдёт в чистую сессию само», «уйдёт туда сразу после документа», «уйдёт следом»), либо ожидание: не длиннее 160 знаков и **только из слов белого списка** — слово ожидания (жду, идёт, идут, waiting, running), свой прогон (тесты, прогон, сборка, копирование, выгрузка, test, run, build; «проверка» — только рядом с ними: «Жду проверки» может быть ожиданием приёмки) и служебные слова («ещё», «сухой», «результата», «около», «the», «for», «to finish»…); число — только перед «мин / сек / ч». Любое другое слово (PR, «вашей», «зависли», «approval», имя ветки) — новость. Ни один отчёт не ждёт пользователя, не с ошибкой и не остановлен; в тексте события приложение не пишет, что сессия ждёт пользователя. Пробуждение без отчётов не отсекается | `hooks/probuzhdeniya.ts` (`skip`), `hooks/register.tsx` |
| 2 | Журнал продолжается: отсечённое пробуждение пишется с полем `dropped` (причина), без `tools`; хранятся последние 3000 записей вместо 300 (~50 в день — около двух месяцев). Файл, который не читается как JSON (оборванная запись), не затирается: сначала копия `sreda-probuzhdeniya.bad-<время>.json` | `hooks/probuzhdeniya.ts` |

Проверка по всем перепискам сессий на сервере: из 146 пробуждений фильтр отсекает 6 — два отказа хука (26.10, 28.10)
и четыре ожидания второго дня. На пяти глобальная только пересказывала. На одном (28.10 04:43, «Waiting for the test
run to finish; I'll report…») сама поставила слежение за журналом проверки — дублировала подпроект, который отчитался
после.

Слепая проверка (Opus, высокий) нашла, что первый вариант — список «слов-новостей» — отсёк бы отчёты, на которые
глобальная должна ответить: «Открыл PR #41, жду проверки.», «Жду вашей проверки.», «Тесты зависли уже 40 минут, жду.»,
"Waiting for approval to run the copy." и ещё 18; и любой отказ хука, в том числе «сообщение с вложением отправьте…».
Поэтому правило перевёрнуто в белый список; все 22 случая — в тестах как «не отсекать». Повторная проверка — 0 блокирующих; по её замечанию «Жду её проверки.», «Жду проверки.», "Waiting to run the tests." тоже не отсекаются.

**Отступление от слов «без чисел»:** число допускается только как длительность («Сухой прогон идёт (около 4 мин),
жду.»); любое другое число («Тесты: 45 из 120, жду.», «2 теста красные…») — новость, пробуждение идёт.

## Почему так

- **Путь к документу передачи не отсекается:** по нему глобальная нашла настоящую причину ошибки.
- **Промежуточные отчёты не отсекаются:** в них бывают цифры, коммиты и шаги, отличить по тексту ненадёжно (ADR 0016).
- **Узкий набор слов, а не широкий:** лучше пропустить шум, чем отсечь отчёт. Ожидание ответа глобальной или
  пользователя («Жду ответа глобальной», «Waiting for the user…») не отсекается — иначе подпроект ждал бы вечно.

## Не вошло

- Сессия R50 MobileData1C7 работает из папки глобального проекта — решение пользователя «Оставить как есть».
- Правила для промежуточных отчётов и повторов — по журналу за больший период.
