## Почему так

- **Правило + заготовка, а не готовый скрипт** (1, 2): у FlowerCore и MobileData1C7 разный запуск (служба, задача
  планировщика, у заказчика — агент); общий скрипт на все случаи стал бы набором условий. Заготовка задаёт порядок и
  откат, проект заполняет «как живёт в работе» — то место, где 27.10 и ошиблись. Сами скрипты проектов — заданиями
  их сессиям после установки (R11): выкладка меняет рабочий сервер, у неё свой скрипт отката и согласие пользователя.
- **`robocopy /E` при установке, `/MIR` при откате:** установка не стирает настройки и журналы в рабочей папке; откат
  возвращает папку ровно в прежний вид.
- **Слепая приёмка** (Opus, высокий; весь выпуск 4–7, диапазон `3faac1c..`): правила 4–5 и 6–7 — сделано, тесты
  79/0 и 41/0, скрипт покрытия на копии плана 28.10 — 239 R. В заготовке выкладки две BLOCKING: копия снималась с
  работающей программы (живая база — не точка возврата; robocopy без `/R /W` ждал бы занятый файл сутками) и проверка
  журнала ловила старые ошибки из того же файла (ложный откат). Исправлено: остановка → копия, `/R:2 /W:2`, сбой копии
  — прежняя версия запускается снова; в журналах смотрятся только строки, дописанные после запуска, `-Proverka`
  журнал не смотрит; откат проверяет код robocopy и прежний номер версии; номер версии — не короче 7 знаков, без
  учёта регистра; вывод сборки — в файл, на экране одна строка; `git fetch` без связи — «не прошло»; первая установка
  (папки нет) — без копии. Проверено запуском на подставной программе: удачная выкладка; неверный номер версии →
  откат к прежней; новая ошибка в журнале → откат (старая строка «Exception» не мешает); `-Proverka`; незаполненная
  заготовка — «НЕ ПРОШЛО … (ничего не менялось)», код 1. В промпт слепой приёмки добавлено «не открывай
  `docs/Находки_проверок.md`» (delivery-control 1.2.1).
- **Оставлено как есть по замечаниям приёмки:** «готово» в файле требований одной задачи (delivery-control) = сделано,
  а в старом плане глобального — неясно (могло значить и «установлено»), поэтому скрипт покрытия его выделяет — разные
  места, не противоречие. Документ автопередачи ссылается на требования, уже записанные в файле проекта, — это не
  задание исполнителю, слова пользователя дословно лежат в том файле. Коммит в Торговля_Связь отправляется в GitHub
  при установке выпуска вместе с остальным.
- **bsl** (4): хук плагина при старте каждой сессии проверяет и при нужде скачивает сервер языка, в том числе в
  проектах .NET и Python; как и навыки 1С (ADR 0005) — включать там, где есть `.bsl`/`.os`/ERT. Проекты выбраны по
  наличию файлов 1С и уже включённому значению.
