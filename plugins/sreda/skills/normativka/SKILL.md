# Нормативка РБ — ilex

Для нормативных документов и разъяснений по РБ первым делом открывать **ilex**: https://ilex-private.ilex.by.
Это платная справочно-правовая система, доступ к ней есть. В ней действующие редакции, история редакций, комментарии
экспертов, «готовые решения», формы и судебная практика. Общий интернет — только если в ilex не нашлось, и тогда
сказать, что в ilex не нашлось. pravo.by и belstat.gov.by с сервера пользователя не открываются.

## Основной путь — программа `ilex.py`

Рядом с этим файлом лежит `ilex.py`: она сама открывает ilex в своём скрытом браузере (Edge) и, если вход потерян,
входит по учётным данным из диспетчера учётных данных Windows (общие, цель `ilex`). Их положил пользователь один раз;
программа берёт их сама, **Claude их не видит, не печатает и не вводит**. Путь к программе — из строки «Base directory
for this skill» в начале навыка (папка меняется с версией плагина):

```
python "<папка навыка>/ilex.py" search "<запрос>" [--tab <вкладка>] [--page N] [--all] [--n 25]
python "<папка навыка>/ilex.py" doc <ссылка> [--find "<слова>"] [--max 20000] [--full] [--out <файл>]
python "<папка навыка>/ilex.py" doc <ссылка> --links [--find "<слова>"] [--max 20000]
python "<папка навыка>/ilex.py" refs <ссылка> [--max 30000]
python "<папка навыка>/ilex.py" backlinks <ссылка> [--seg M<абзац>] [--tab <вкладка>] [--page N] [--all] [--n 25]
python "<папка навыка>/ilex.py" editions <ссылка> [--n 0]
python "<папка навыка>/ilex.py" status
python "<папка навыка>/reestr.py" new <реестр.md>
python "<папка навыка>/reestr.py" add <реестр.md> <вывод refs/search/backlinks.txt> --from "<документ или запрос>"
python "<папка навыка>/reestr.py" check <реестр.md> [<отчёт.md>]
```

- **Ссылку давать полностью** — `https://ilex-private.ilex.by/view-document/BELAW/238448`: короткую `/view-document/…`
  Git Bash превращает в путь к файлу (`C:/Program Files/Git/view-document/…`), и программа вернёт код 5.
- `search` — «Найдено документов: N», обзор ilex по запросу и выдача: дата и состояние, название, адрес, по 25
  (около 15 с). `--tab` — одна вкладка, `--page 2` — следующие 25, **`--all` — все страницы до конца** («военно-
  врачебная экспертиза варикоцеле»: 344 из 344 за 49 с; листание ограничено 200 с — не дошло, «ВНИМАНИЕ … продолжить
  --page N --all»). В конце — «[конец списка]» или подсказка про следующие страницы.
- `doc` — **всегда весь текст**: программа нажимает «Экспорт в Word» и разбирает файл (закон 57-З — 63 тыс. знаков
  за 21–23 с); страница сама подгружает длинный документ частями и середину теряет (57-З терял ст. 10), поэтому её
  текст не берётся. Word не скачался — прокручивает по шагам (порядок тот же, но оглавление и одинаковые строки вроде
  «Исключен.» могут смешаться; прокрутка ограничена 150 с — не дошла до конца, в выводе «ВНИМАНИЕ … конец не
  собран»). `--full` оставлен для совместимости. `--find "строка 001"` — куски вокруг всех слов (все; не влезли в `--max` — пометка «обрезано … кусков k из N»); так длинный документ
  читать дешевле. `--out <файл>` — весь текст в файл (папка scratchpad, не репозиторий: текст платный), дальше — Grep.
  Без `--find` печатаются первые `--max` знаков.
- `doc --links` — абзацы с номерами (`M100391 | 4. Первичный учетный документ составляется…`) и все ссылки документа:
  абзац, тип, текст ссылки, адрес. С `--find` — программа идёт «Поиском в документе» ilex от совпадения к совпадению
  (с учётом окончаний) и печатает абзацы с совпадениями и их ссылки: Инструкция 1/1 (332 тыс. знаков), «Варикоцеле» —
  22 с, «статьи 45» — 6 совпадений, 39 с. Без `--find` — прокрутка всего документа (до 150 с; не дошла — «ВНИМАНИЕ»).
  `--out` и `--full` с `--links` не действуют, больше вывода — `--max`. Номер абзаца нужен для `backlinks --seg`.
- `refs` — **все акты, упомянутые в документе**, по всему тексту (Word): с реквизитами (дата | номер | вид | сколько раз
  | где), названные без реквизитов («Положением о военно-врачебной экспертизе | 5») и ссылки ilex на другие документы
  с адресами. Закон 1914-XII: 29 актов, 14 названий, 95 ссылок, около 2 мин 10 с. Каждая строка — в реестр.
- `reestr.py` — реестр источников и сверка отчёта (без ilex, мгновенно): `new` — заготовка таблицы (существующий
  реестр не перезаписывает); `add` — дописать в реестр всё из вывода `refs`, `search` или `backlinks`, сохранённого в
  файл, чего там ещё нет (по номеру, адресу, названию целиком), статус пустой — заполнить при чтении; вывод с пометкой
  об обрезке («[обрезано», «ВНИМАНИЕ», не все страницы) — код 1 и подсказка, как переснять; `check` —
  замечания по реестру (статус, откуда узнали, где прочитан, причина и попытки) и по отчёту (фразы «не изучен»,
  «не открыт», «не найден», «разъяснений нет» без причины из закрытого списка). Код 0 — замечаний нет.
- `backlinks` — «кто ссылается» на абзац (`--seg M100391` или `#M100391` в ссылке) или на весь документ: число
  материалов по вкладкам (определение ПУД в законе 57-З: «Законодательство 0, Аналитика 855, Формы 65, Судебная
  практика 0») и список — дата и
  состояние, название, адрес, свежие сверху, по 25. `--tab Законодательство|Аналитика|Формы|"Судебная практика"` —
  одна вкладка, `--page 2` — следующие 25, **`--all` — все страницы** (Закон 1914-XII: 309 из 309 за 43 с). Около
  25–50 с.
- `editions` — все редакции документа: «Действующая редакция» / «Недействующая» / «С изменениями, не вступившими в
  силу», «ред. от …» и адрес каждой (в панели ilex ссылок нет — программа открывает строки по очереди: Закон 57-З,
  8 редакций — 66 с). Строк нет — «ВНИМАНИЕ», код 5.
- `status` — есть ли вход и когда программа входила последний раз; **только смотрит, сама не входит** (код 0 — вход
  есть, 3 — нет). `search`, `doc`, `refs`, `backlinks` и `editions` входят сами, когда нужно, — `status` перед ними не нужен.
- Запускать без `-I`: playwright стоит в пользовательских пакетах Python. Тайм-аут команды — 300000 мс: одновременные
  запуски из разных сессий ждут друг друга до 90 с, потом код 6.
- Вход потерялся посреди запроса (выбили) — программа сама входит снова и повторяет запрос раз.
- **Все сессии сервера делят один вход программы** (один профиль браузера, запуски по очереди), поэтому друг друга не
  выбивают: проверено 30.10.2026 — два поиска одновременно, второй подождал 14 с, нового входа нет. Выбивает только
  вход **в другом месте**: встроенный браузер, другой компьютер, сотрудник заказчика. Поэтому на сервере, где программа
  есть, в ilex через встроенный браузер не входить и пользователя об этом не просить.

Коды выхода и что делать:

| Код | Что случилось | Что делать |
|---|---|---|
| 0 | готово | — |
| 2 | нет учётных данных `ilex` в Windows | сказать пользователю окном: положить их самому командой `cmdkey /generic:ilex /user:<почта> /pass` в обычном PowerShell (пароль спросит сама команда); до этого — встроенный браузер |
| 3 | вход теряется сразу после входа программы (или включено ограничение по частоте, а программа входила недавно) | не повторять в цикле и **не просить пользователя войти**: вход сейчас у человека, которого выбивать нельзя. Отложить проверку нормы (до времени из сообщения, если оно есть) и сказать об этом одной строкой; срочно — сказать пользователю, что войти может он сам, выбив того сотрудника, — решает он |
| 4 | ilex не пустил после ввода учётных данных | сказать пользователю: пароль сменился или подписка закончилась — обновить учётные данные той же командой `cmdkey`; следующий запуск войдёт сразу (неудачный вход лимит не трогает) |
| 5 | страница не загрузилась | повторить один раз; снова 5 — встроенный браузер, если там уже есть вход |
| 6 | другая сессия занимает ilex дольше 90 с | повторить через минуту |
| нет Python, playwright или Edge | программа на этой машине не работает (стоит на сервере EM-WIN-160) | встроенный браузер |

**Учёткой пользуются и сотрудники заказчика, а ilex пускает под одной учёткой только один вход:** новый вход
закрывает прежний. Программа входит только когда вход потерян; ограничения по частоте сейчас нет
(`MIN_RELOGIN_MINUTES = 0`, решение пользователя «сейчас любое количество раз» (пользователь, 30.10.2026)). Каждый вход — в журнале
`%LOCALAPPDATA%\ilex-client\log.txt`; «Продолжить» в журнале — значит, программа кого-то выбила. Если ограничение
включат (число больше 0), его не обходить и не удалять `state.json`.

## Полное изучение — все документы по цепочке ссылок

Задача пользователя (30–31.10.2026, ADR 0024, 0025): изучать тему, переходя по ссылкам из документа в документ, —
**все** нормативные акты подробно, «все ссылки пересмотреть», время не важно; «каждый документ должен пройти по
цепочке с разъяснениями, с пояснениями, мнениями экспертов, с описаниями». В отчёте нет «не изучен», «не открыт»:
«не получилось изучить» — только когда документ не найден никакими средствами, и с конкретной причиной («нет
доступа», «не опубликован», «не найден ни в одном источнике»). Пределов по числу материалов и глубине нет.

Почему это записано (разбор 31.10.2026, «Военная годность»): первый отчёт опирался на 2 акта — не запускались
`--links` и `backlinks`, акты, на которые ссылается прочитанный Закон (Положение № 868 → перечень 8/14), не
открывались, «разъяснений нет» — после одного обрезанного поиска, документ из файла пользователя не искали по
номеру, а слепая проверка не проверяла полноту.

Порядок:

0. **Документы пользователя — сначала** (навык `sreda:izuchenie-dokumentov`): опись и факты с местом. Всё, что в них
   названо (номер акта, имя файла вроде `постановление_МО_МЗ_2020_8-14.pdf`, код диагноза, форма справки), — сразу в
   реестр и в ilex по номеру: `search "8/14"`.
1. **Дорожная карта** до поиска: какие виды источников отвечают на вопрос — закон или кодекс, указ, постановление
   Совмина, ведомственные акты (инструкции, перечни, положения), письма и разъяснения госорганов, аналитика и
   ответы экспертов, формы, судебная практика. Карта — в начале реестра; по ней проверяется полнота.
2. **Реестр** — `reestr.py new <реестр.md>` в папке задачи или scratchpad (не в публичный репозиторий): строка на
   **каждый** документ, о котором узнали, — из поиска, текста (`refs`), ссылок абзаца, «кто ссылается», документов
   пользователя; выдачу `search --all` и `backlinks --all`, сохранённую в файл, — `reestr.py add`. Статус: «прочитан»
   (где), «не относится» (почему и где смотрели или «по названию»), «недоступен» (причина из списка и попытки и в
   ilex, и вне его). У прочитанного нормативного акта — графа «Цепочка»: что сделано по нему дальше (refs, backlinks
   по нужным абзацам — числа по вкладкам и строки реестра, которые из них прочитаны); пустая — замечание `check`.
3. **Поиск** — `search --all` по словам вопроса и по названиям из карты: обзор ilex над выдачей и **все названия
   выдачи до конца** (первые 25 из 344 — не выдача); вкладки «Аналитика», «Формы», «Судебная практика» — `--tab`.
4. **Каждая норма целиком** — `doc --out` (дальше Grep) или `doc --find`; вывод — только по прочитанному месту.
   **Редакция** — `editions`: на дату события (освидетельствования, сделки, периода) и на сегодня; переходные
   положения; «С изменениями, не вступившими в силу» — что меняется и с какой даты.
5. **Что упоминает норма** — `refs` по каждой прочитанной норме (вывод — в файл scratchpad): все акты с реквизитами,
   названные без реквизитов и ссылки ilex — в реестр командой `reestr.py add <реестр.md> <файл> --from "<норма>"` (`refs --max 100000`, чтобы вывод не обрезался); каждый, относящийся к вопросу, открыть и прочитать нужное место (шаг 4).
6. **Нужные абзацы и их ссылки** — `doc --links --find "<слова>"`: НУЛ с адресом — прочитать норму, на которую
   опирается; РДД — каким актом изменено; ПОТ — что утратило силу.
7. **Кто ссылается** — `backlinks --seg M<абзац>` по каждому нужному абзацу и `backlinks` на документ: число по
   вкладкам и **все названия на всех страницах** (`--all`). Каждый материал, относящийся к вопросу по
   названию, — открыть и прочитать (письма Минфина, МНС, ведомств; готовые решения, вопрос-ответ, статьи,
   путеводители; формы; суды). Сотни названий — отдельному агенту: он листает все страницы и возвращает список
   относящихся с адресами (сам ничего не решает о выводе).
8. **Дальше по цепочке**: от каждого прочитанного материала — к нормам и документам, на которые он опирается (`refs`,
   `--links`), и снова шаги 4–7. **Остановка — когда шаг не даёт нового документа, относящегося к вопросу**, а не по
   числу или глубине.
9. **Отрицательный вывод — с доказательством.** «Разъяснений нет» — с перечнем запросов и вкладок, которые дали ноль.
   «Недоступен» — только после всех попыток: ilex по номеру, по названию, по виду и дате, `editions`, «кто
   ссылается» на акт, который его упоминает; затем сайт органа и общий интернет — и попытки записать в реестр.
10. **Перед отчётом** — `reestr.py check <реестр.md> <отчёт.md>`: код 0, иначе исправить. В начале отчёта — блок
    для проверяющего: сколько документов в реестре и сколько прочитано, на какую дату проверена актуальность, чего
    нет и почему, что сделать до использования. У каждой ссылки — откуда она: `[ilex, ред. от …]`, `[сайт органа]`,
    `[интернет — проверить]`, `[знания модели — проверить]`; цитата должна подтверждать вывод, а не только стоять
    рядом.
11. **Слепая проверка полноты** (Opus, высокий): проверяющему — слова пользователя дословно, дорожная карта, реестр
    и отчёт. Он сам запускает `refs` и `backlinks` по ключевым нормам и ищет документы, которых нет в реестре, и
    выводы без прочитанного места; найденное — в реестр и снова шаги 4–8.

## Запасной путь — встроенный браузер

- ilex открывается во **встроенном браузере** (инструменты `mcp__Claude_Browser__*`). Его профиль общий для всех
  сессий настольного приложения; если пользователь вошёл там с «Запомнить меня», вход уже есть.
- Свою вкладку — `preview_start` с `url`, не трогая чужие: в том же браузере могут работать другие сессии.
- Сюда — только если программы на этой машине нет или она вернула 5 дважды. Код 3 сюда не ведёт.
- Вход истёк (адрес ушёл на `/public/service-login` или страница просит почту и пароль): **почту и пароль в браузер не
  вводить, не искать и не спрашивать**. Где программа есть — запустить её (она войдёт сама). Где её нет — попросить
  пользователя окном: открыть панель браузера (Ctrl+Shift+B), войти в ilex самому с галочкой «Запомнить меня» и нажать
  «Вошёл, проверь». Вход в браузере выбьет вход программы и сотрудника заказчика, и наоборот.
- Не выходить из учётной записи, не менять её настройки и профиль, «Избранное» и подписки — без просьбы пользователя.
- Нет ни программы, ни встроенного браузера (сессия не на сервере и не в настольном приложении) — сказать
  пользователю, что ilex отсюда недоступен, и искать в общем интернете с этой оговоркой.

## Поиск в браузере

1. Поиск сразу по адресу: `https://ilex-private.ilex.by/search?query=<запрос, закодированный для URL>`.
   Через 2–3 с — `get_page_text`. Наверху «Найдено документов: N», вкладки «Все / Законодательство / Аналитика /
   Формы / Судебная практика», часто — «Обзор документов ilex по запросу» (сводка с шагами) и «Умная страница».
2. Список ссылок выдачи удобно достать `javascript_tool`:
   `[...document.querySelectorAll('a[href*="/view-document/"]')].map(a => a.href + ' | ' + a.innerText.slice(0, 100))`.

## Чтение документа в браузере

- Текст подгружается после открытия: подождать 3–4 с и читать `get_page_text` или
  `javascript_tool` с `document.body.innerText`. Первое чтение сразу после открытия даёт только оглавление.
- Длинный документ и приложения подгружаются частями: нужный пункт — через «Поиск в документе» или пункт оглавления,
  затем снова читать.
- Полное изучение — тем же порядком, что выше. Ссылки в тексте — не `<a href>`, а элементы `simple-link`
  (в прежнем оформлении и `document-link`) с атрибутами `infobank`, `docid`, `segmentid`, `link-type`; адрес —
  `/view-document/<infobank>/<docid>#M<segmentid>`. Номер абзаца — пустой `span.not-visible-element` с `id="M<номер>"`
  внутри абзаца (в прежнем оформлении — `span.segmentId-element[segmentid]`). Оглавление — `il-content-item`
  с классом `contents-node-text-M<номер>`; поиск в документе — поле `il-doc-search-ab-test-input input`, счётчик «k/N».
  «Кто ссылается» — значок (i) у абзаца или сразу адрес `/backlinks/<база>/<номер>/<абзац>`; вкладки — кнопки
  (адрес не меняется), следующие 25 — кнопка листания внизу. Редакции — значок «Редакции» в панели слева.

## Выдача и документы (оба пути)

- У документа в выдаче — дата и состояние: «Действующая редакция» или «Утратил силу или отменен». Брать действующую;
  утратившую — только если вопрос про прошлый период, и тогда проверить, какая редакция действовала на ту дату.
- Ссылки на документы — вида `https://ilex-private.ilex.by/view-document/<БАЗА>/<номер>/...`, где `BELAW` —
  законодательство, `BEPBI` — статьи, готовые решения и комментарии, `BEPPN` — путеводители, `BEENC` —
  энциклопедии, `BEQUEST` — вопрос-ответ, `BEKOR` — сборники и корреспонденции счетов. Короткий адрес
  `https://ilex-private.ilex.by/view-document/BELAW/<номер>` тоже открывается.
- Запрос — словами вопроса и названием документа или формы: «форма 4-ф затраты», «инструкция по бухгалтерскому учету
  запасов», «больничный в выходной день». Мало толку — переформулировать или сузить словами документа.
- В шапке документа — «Справка», «Редакции», «Сравнить с предыдущей»: так проверять, с какой даты действует норма
  и что поменялось. Плашка «Подготовлена редакция документа с изменениями, не вступившими в силу» — есть будущая
  редакция (`editions` покажет её дату).
- В тексте нормы встречаются примечания «КонсультантПлюс: примечание.» со ссылкой на письма и разъяснения — это
  подсказка ilex, не часть нормы; письмо из примечания открыть, если оно про вопрос.
- Внутренние запросы сайта (`/backend-client/...`) работают только с токеном страницы — не пытаться их вызывать и
  доставать токен.

## Что записывать

- В ответ и в базу знаний проекта: название документа, номер и дата, редакция («ред. от …»), пункт или статья, ссылка
  ilex, дата проверки. Разъяснение эксперта («Готовое решение», «Вопрос-ответ», статья) — отдельно от нормы, с автором
  и датой «актуально на».
- Тексты ilex — платный материал: в ответ — нужный пункт или короткую цитату, не весь документ; в публичные
  репозитории — только реквизиты и ссылку, без текстов.
- Нашёл в ilex, но вывод держится на толковании, а не на прямой норме, — так и сказать.
- **Журнал проверенного** в базе знаний проекта: акт, редакция, дата сверки, нужные пункты и абзацы (`M…`). В
  следующий раз брать оттуда и проверять только, не вышла ли новая редакция (`editions`).
