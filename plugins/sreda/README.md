# sreda — «Среда работы»

Весь способ работы пользователя с Claude в одном плагине, чтобы он стоял на каждом компьютере и не искался по частям.

| Часть | Что даёт |
|---|---|
| Навык `sreda:kak-rabotat` | Правила: разобраться до конца (код, базы, интернет, законы), решить и показать варианты с обоснованием, не применять без «да»; любой вопрос — окном с кнопками и в панель; слова пользователя дословно; замечания копить и исправлять одним прогоном; чужие системы — только по команде; секреты не вводить; PR сливать только по «да» на каждый; рискованные изменения сервера — сначала откат |
| Навык `sreda:globalnyj-proekt` | Глобальный проект и подпроекты: когда предложить (после постановки начальной задачи), устройство глобальной папки, новый подпроект с заданием, сессии подпроектов, порядок общения (с пользователем — по-русски, между сессиями — по-английски), приёмка и сверка; шаблоны файлов и сообщений |
| Панель «Ждут ответа» | Мод рядом с чатом: все неотвеченные вопросы с пояснениями и кнопками; не исчезает, пока не ответишь |
| Зависимости | `delivery-control` (контроль сдачи, `diagnose`) и `autohandoff` (передача в чистый контекст) включаются вместе с `sreda` |

Краткие правила попадают в `~/.claude/CLAUDE.md` установщиком маркетплейса (блок `xebcyp-plugins`), подробности — в
навыках. Местное (пути, диски, серверы, VPN) остаётся в `~/.claude/CLAUDE.md` компьютера вне блока.

## Панель «Ждут ответа»

Окно с вопросом в чате закрывается, если написать что-то, не нажав кнопку, и потом вопрос трудно найти в длинной
переписке. Панель показывает все вопросы, на которые ещё нет ответа: откуда вопрос (проект, подпроект), что решаем и
зачем, кнопки вариантов и что будет при каждом.

- Вопрос попадает в панель сам из окна AskUserQuestion — Claude не тратит токены на запись в файл
  `~/.claude/zhdut-otveta.json` (общий для всех сессий компьютера).
- Ответ в окне сразу убирает вопрос из панели в `~/.claude/zhdut-otveta-arhiv.json`: в рабочем файле только открытые.
- Кнопка в панели сразу отвечает на открытое окно, даже в другой сессии (та узнаёт из файла за 1–2 секунды). Окна
  уже нет (пользователь написал что-то другое) — ответ приходит в чат сообщением, как напечатанный; пока сессия
  занята ходом, он ждёт в плагине: повтор вопроса окном сразу получает его без окна, иначе сообщение — после хода.
- Под кнопками — поле «Свой ответ…»: текст с Enter уходит так же, как кнопка, — в открытое окно (как «Other»), иначе
  сообщением в чат.
- Вопрос, где можно выбрать несколько вариантов, — флажки ☐/☑: нажатие только отмечает, ответ уходит кнопкой
  «Ответить: выбрано N» (свой вариант из поля добавляется к отмеченным).
- Вопрос с командой, которую пользователь запускает сам (блок ``` в вопросе или в `preview`, или строка `preview`,
  которая начинается как запуск: `powershell …`, `& "…"`), — команда блоком кода со своим значком копирования.
  Окно с кнопкой «Запустил» без блока команды плагин не показывает, а возвращает Claude с правилом.
- Записать в файлы панели сам Claude не может — плагин отклоняет запись: ручная запись плюс тот же вопрос окном
  давали в панели дубль. Ответили текстом, не нажав кнопку, — Claude убирает вопрос инструментом `otvecheno`.
- Написали о другом, не ответив (окно в чате закрылось), — вопрос **остаётся** в панели с пометкой «окно закрылось
  вашим сообщением». Приложение говорит Claude «считай сообщение ответом, не спрашивай снова»; плагин заменяет это на
  «не отвечено»: Claude делает новое задание и в конце хода задаёт вопрос окном снова.
- Панель открывается сама в начале сессии. Закрыли крестиком — откроется снова с новым вопросом (любой сессии);
  вручную — команда `/zhdut-otveta`.
- В сессии подпроекта (её папка названа в строке «**Где:**» реестра `docs/Подпроекты.md` глобального проекта в
  соседней папке) панель сама не открывается: вопросы пользователю задаёт глобальная, и там же их видно.

Формат файла (архив — тот же, с `status: "answered"`, `answer`, `answeredAt`, `answeredIn`):

```json
{ "items": [ { "id": "kratkij-kod", "from": "Проект · заголовок", "question": "Что решаем?",
  "options": [ { "label": "Вариант", "desc": "Что будет" } ], "status": "open", "asked": "2026-10-25",
  "session": "id сессии, где открыто окно" } ] }
```

## Модель и уровень усилий

Сессия сама выбирает уровень, пользователь ничего не нажимает (ADR 0011, `hooks/uroven.ts`):

- в начале хода мод оценивает сообщение (объём, вопросы, пункты, слова о поиске ошибок, решениях и «не помогло») и
  ставит Opus средний, высокий (один признак сложности) или сверхвысокий (два и больше); текущий — в строке под полем
  ввода «Усилия: …» (ADR 0013: диапазон от среднего до сверхвысокого, только Opus 5.5);
- по ходу сессия поправляет уровень инструментом `uroven`; оценка понижает уровень на длинной переписке (больше
  40 тыс. токенов) только со второго сообщения подряд — сброс кэша дороже разовой экономии;
- задание подпроекту задаёт уровень первой строкой `Effort: medium|high|xhigh`;
- вызовы агентов и подпроектов выправляются в рамки: любая модель → Opus, низкий → средний, максимум →
  сверхвысокий, слепая проверка — Opus высокий, `Explore` без модели — Opus.

**Ручной режим** (ADR 0012) — уровень основной сессии ставите вы в программе, мод его не меняет и не держит в рамках
(«низкий» и «максимум» можно); в строке — «вручную · высокий». Рамки агентов и подпроектов остаются.

- `/uroven ручной` — для проекта: пишет в его `.claude/sreda.json` `{"uroven": "ручной"}` (прочие ключи файла
  сохраняются; файл можно закоммитить — режим будет на всех ПК); `/uroven авто` — вернуть выбор моду; `/uroven` —
  кто сейчас выбирает.
- Сменили уровень в программе посреди сессии — мод замечает это и до конца сессии уровень не трогает (вернуть —
  `/uroven авто`).

## Строка под полем ввода

Одна строка плагина (`hooks/stroka.ts`), части через « · »:

```text
Усилия: высокий · TKN 152K · 5H ▪▪▪▫▫▫▫▫ 37% до 18:40 · 7D ▪▫▫▫▫▫▫▫ 12% до пт
```

- **Усилия** — уровень этой сессии (раздел выше);
- **TKN** — токены переписки в тысячах, как их считает автопередача `autohandoff` (пороги 150K–200K/250K);
  «TKN —» — в новой сессии до первого ответа модели;
- **5H** и **7D** — израсходованная доля лимитов подписки за 5 часов и за неделю: шкала, процент и когда лимит
  сбросится (сегодня — время, завтра — «завтра 9:00», дальше — день недели).

Обновляется после каждого ответа и раз в 30 с (лимит 5 часов тратят и другие сессии). Шрифт и цвет строки задаёт
приложение. Заменяет чужой мод `ctx` (шкалы CTX/5H/7D): его процент окна контекста ничего не говорил о пороге
передачи.

## Защита git

- **«git add -A», «git add .», «git commit -a»** не выполняются, если в папке есть изменённые файлы, которые эта
  сессия не правила (её файлы — те, что она писала инструментами Write/Edit): Claude видит список чужих и добавляет
  свои по именам. 25.10 такая команда забрала в коммит файлы параллельной сессии.
- **«git commit -m» с кириллицей** не выполняется: сообщение — через файл, `git commit -F файл`.

## Пауза глобального проекта

`/pauza` или слова «поставь на паузу», «нужно перезагрузить» в глобальной сессии (в её папке — `docs/Подпроекты.md`)
включают паузу: Claude рассылает её подпроектам и отвечает только строкой состояния, а плагин не пропускает новые окна
вопросов и запуск сессий. `/prodolzhit` или «продолжай» снимает паузу. Пауза переживает перезапуск программы.

## Пустые пробуждения

Пробуждения глобальной от подпроектов (`<side-sessions-event>`) записываются в `~/.claude/sreda-probuzhdeniya.json`
с пометкой, шум ли это (нет отчётов, отказ хука, повтор прошлого отчёта). Настройка `probuzhdeniya`: `zapis` (по
умолчанию) — только запись; `filtr` — шум сессию не будит. Фильтр включается после просмотра записи (ADR 0015).

## Установка

```
/plugin install sreda@xebcyp-plugins
```

Установщик маркетплейса (`scripts/install.ps1`, `install.sh`) включает его сам. Отдельный плагин `zhdut-otveta`
заменён этим и убран из маркетплейса. Убранные плагины Claude Code удаляет сам (раздел Flagged в `/plugin`); пока
старая копия включена, панели будет две — выключите `zhdut-otveta` в `/plugin` и удалите строку
`zhdut-otveta@xebcyp-plugins` из `~/.claude/settings.json`.
