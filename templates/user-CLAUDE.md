## Среда работы

Кратко — здесь; подробно — плагин `sreda` («Среда работы»): навык `sreda:kak-rabotat` (все правила) и
`sreda:globalnyj-proekt` (глобальный проект и подпроекты), панель «Ждут ответа». Вместе с ним включены
`delivery-control` и `autohandoff`. Правила проекта (его CLAUDE.md, его навыки) главнее; местное (пути, серверы,
диски) — ниже, вне этого блока.

## Решения: разобраться, решить, показать — не применять

- **Разобраться до конца самому:** каждый вариант — по коду и данным базы/программы, по интернету, по нормативке и
  законам (РБ, если задача учётная). «Может быть», «проверим потом» — только если код или данные недоступны, и тогда
  сказать, что именно не проверено.
- **Решить самому и показать:** варианты, выбранный и почему — понятно для человека без специальных знаний. Не
  спрашивать «какой выбираете».
- **Не применять, пока я не согласился:** ни код, ни данные, ни настройки, ни ADR. Согласие на одно решение не
  распространяется на другие. Мелкие технические решения внутри согласованной задачи — делать и упомянуть в отчёте.
- **Слияние PR — только после моего «да» на этот PR**, спрашивать каждый раз.

## Как работать

- **Разбирать до происхождения и записывать:** поле, регистр, параметр, на который ссылаюсь, — откуда значение
  (ввод или расчёт, каким кодом), где используется; записать в базу знаний проекта. Записанное — брать оттуда.
- **Мои слова — дословно**, требования — с номерами. **Замечания при проверке — копить** дословно с номерами, код не
  трогать; исправлять всё одним прогоном по команде.
- **Закон: задание исполнителю (подпроект, субагент, сессия) — все мои слова по теме дословно, проверка по каждому.**
  Найти в плане все требования по теме, не одно-два; неясное — спросить меня окном до задания; в «Как проверить» —
  строка на каждое требование; сначала образец, потом весь объём; приёмка — против моих слов, отступление — мне до
  выкладки (`sreda:kak-rabotat`, раздел 4).
- **Не выяснять заново:** перед новой проверкой, исследованием или пунктом — поиск в списке открытых пунктов,
  `docs/adr/` и базе знаний проекта; уже сделанное — брать оттуда.
- **Выводы — по полным данным:** о процессе или данных — по всем записям или журналу программы, не по нескольким
  примерам. Прогон — сначала минимальный, который отвечает на вопрос; больший — с обоснованием.
- **Сначала доступ:** до работы проверить, что нужное доступно (база, сервер, папка, права); закрыто и самому не
  открыть (VPN не поднялся и т. п.) — сказать сразу, молча не подменять копией или обходом.
- **Чужие системы** (базы и таблицы заказчика, чужие скрипты и настройки) — сначала разобраться и записать, менять
  только по команде. Файловые базы 1С (DBF, 1CD) по сети не править — работать на локальной копии.
- **Рискованные изменения сервера и сети** — сначала скрипт отката; шаги с правами администратора — мне скриптом.
- **Отчёты нарастающим итогом (статистика, налоги):** нарастающий итог — из учёта целиком; графа «за квартал/период»
  = свой нарастающий итог − графа «с начала года» **сданного** прошлого отчёта (обратный счёт), чтобы прошлый отчёт +
  квартал = новый итог и программа приёма не отклоняла из-за округлений; квартал по учёту — только для сверки.
- **Журнал проекта — два файла:** файл передачи — только текущее состояние (до ~150 строк, читается при старте),
  сделанное — в `docs/История_сессий.md` (только дописывается, при старте не читается); коммит журнала — при передаче.
- **Результат, который я смотрю** (PDF, отчёт, страница, картинка), — перед сдачей отрисовать и посмотреть самому;
  хранить в проекте, папка обмена — только для передачи.
- **Своя папка и свои файлы:** сессия работает в папке своего проекта (новая тема — в своём проекте, не в чужом);
  второй поток в той же папке — в своём worktree; в папке есть чужие незакоммиченные изменения — коммитить свои файлы
  по именам, не `git add -A`; worktree и ветку удалять тем же шагом, что и слияние.
- **Секреты:** логины и пароли самому не вводить, ключи не печатать в чат и не коммитить.
- **Имён клиентов и названий конфигураций нет в общих и публичных файлах** — там «База_N».
- **Начало сессии в git-проекте:** `git fetch` и `git status -sb`; отстаёт и изменений нет — `git pull --ff-only`.
- **В чате кратко:** пока идёт разбор — только крупные шаги.

## Контроль сдачи работы

- Задача больше пары файлов или с несколькими требованиями — навык `delivery-control`; ошибка, падение, расхождение
  цифр — навык `diagnose` (сначала команда, которая воспроизводит ошибку). Мелкое — просто сделать и проверить.
- **Независимые проверки** (чтение плана, слепая приёмка против моих слов) — в средних и больших задачах;
  делает свежий субагент без моих заметок и плана. Разрешение даю заранее — не спрашивать, сказать одной строкой, что
  запускаю проверку. Проверяющему — мои слова по теме дословно, а не задание; ответ — таблица «требование →
  доказательство → вердикт»; до проверки исполнитель сам проходит `docs/Находки_проверок.md` проекта.
- Субагентам — только когда выгоднее одного агента (много прочитать и мало вернуть, 2–3 независимые части, большой
  объём). Термины и решения — в `GLOSSARY.md` и `docs/adr/`.
- «Готово» — только после проверки; что не проверено — сказать прямо.
- **Модель и уровень усилий** — выбирать самому, меня не спрашивать: только Opus 5.5, средний/высокий/сверхвысокий, по
  умолчанию средний; Sonnet, Haiku, Fable, «низкий» и «максимум» не брать; слепая проверка — Opus высокий (мод и
  правила — sreda:kak-rabotat, раздел 10).

## Глобальный проект и подпроекты

- После постановки начальной задачи с несколькими независимыми частями или на много сессий — **самому предложить**
  глобальный проект с подпроектами (навык `sreda:globalnyj-proekt`), окном, с обоснованием.
- Я говорю только с глобальной сессией, по-русски. Сессии подпроектов — по-английски; меня не спрашивают, вопросы шлют
  в глобальную, она задаёт их окном и в панели с пометкой подпроекта. Мои слова в заданиях — дословно по-русски.
- Длинные сессии — в чистый контекст по документу передачи (`autohandoff`): около 200 тыс. токенов — подпроект со
  150 тыс. (с 250 — без проверки), глобальная со 150 (с 200); перед передачей — отсчёт 15 с с «Паузой»; расход токенов — `sreda:kak-rabotat`, раздел 9.
- Новая задача подпроекту — в чистой сессии (очистка или новая сессия); уточнения, ответы и следующий шаг той же
  задачи — в той же, очистка по порогам (`sreda:globalnyj-proekt`, раздел 4). Сессия подпроекта — только в его папке;
  новая сессия — в реестр в тот же день.
- **Пауза** («поставь на паузу», «нужно перезагрузить»): разослать паузу, дальше — только строка состояния по каждому
  подпроекту и «можно перегружать»; новые окна, установки и задания — после «продолжай». Открытые вопросы на паузе
  окнами не повторять — они ждут в панели.
- **Одна проверка — один владелец:** установку проверяет подпроект по номеру версии, который сообщает сама программа,
  и присылает его; глобальная сверяет номер с ожидаемым, а не проверяет второй раз.
- **Общее для нескольких подпроектов** (правила учёта, пути, группы, настройки) — в одном файле глобального, подпроекты
  ссылаются, а не копируют. Ссылка на решение — с проектом: «ADR глобального 0018», «ADR <подпроект> 0018».
- «Закоммитить и отправить» глобальному проекту — команда и всем его подпроектам: каждый отправляет своё в GitHub
  (закрытые репозитории); занятый — после текущей операции. Глобальная проверяет, кто занят, ведёт отправку до
  последнего подпроекта и даёт сводку, что отправлено и что ждёт (`sreda:globalnyj-proekt`, раздел 7).
